# Offline notebook editor

Build: `npm ci --ignore-scripts && npm run build`. Test: `npm test`. The generated `Sources/WorkJournal/Resources/NotebookEditor` directory is committed so normal Swift app builds require no Node, npm, network, or development server. The build script includes all actual runtime package licenses. The SwiftPM target must copy this directory as a resource; packaged `.app` builds must retain the generated SwiftPM resource bundle.

Native smoke test: `Editor/test/native-test.sh` from the repository root. It compiles the actual controller in a temporary harness using synthetic notes and runs a real hidden WKWebView; desktop/WebKit process access is required. The harness changes only the module import and resource accessor for standalone compilation. It does not access the journal database.

Native integration:

- Own a `NoteEditorController` and embed `NoteEditorView(controller:)`.
- Set `assetProvider`, `importImage`, `openAsset`, `openNote`, `onChange`, `onError`, and `onSaveRequested`.
- `load(noteID:markdown:revision:force:)` creates a new session when changing notes. Same-note calls do nothing unless `force: true`; autosave acknowledgements must not replace the editing state.
- `flush() async throws -> NoteEditorUpdate` waits for ready and composition. Call it before selection changes/unmounting/quitting, and persist the result. Failures must keep the note open and retain its recovery draft.
- Updates contain `noteID`, `sessionID`, monotonic `sequence`, and `markdown`. Root must validate the selected note and current `controller.sessionID`. Content-process recovery creates a new session with the most recently received text, so reset the root sequence gate for this new session.
- `latestUpdate` exposes the last accepted full document. `isReady` is observable. `command(_:)` includes `document`, `source` and toolbar command names.

CommonMark and GFM use Tiptap Markdown. Rich style blocks and merged tables use HTML generated by ProseMirror's DOM serializer, with all attributes and text escaped. Footnote definitions are preserved as visible raw blocks; unknown HTML and math remain visible literal syntax. Original source is retained byte for byte until an actual edit. Switching mode rebuilds the document history; the footer explicitly explains that undo history starts anew per mode. Links only open by an explicit open action or Command-click. Strict `workjournal-note://<UUID>` links dispatch `openNote`; root must apply its normal save barrier before selecting that note. HTML comments and unsupported custom elements remain visible inert source, and serialized code fences exceed every backtick run in their contents. Images never fetch remotely.

Image import uses original caret bookmarks mapped through subsequent transactions, one-time callback tokens, and note/session checks. File selection supports validated image data up to 128 MiB; paste/drop accepts up to 16 MiB and 20 images per event. Native decoding corrects orientation and creates PNGs up to 6000 pixels on the longest side (at most 100 million input pixels). Animated images inserted this way become their first frame; existing imported asset bytes are untouched. Only raster image assets of the current note are exposed by the local scheme.
